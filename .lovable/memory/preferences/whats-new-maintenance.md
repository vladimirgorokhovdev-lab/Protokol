description: При добавлении новой пользовательской функции обновлять src/lib/whatsNew.ts и Руководство
type: preference
---
**Правило:** Каждый раз, когда я реализую НОВУЮ пользовательскую функцию (не багфикс, не рефакторинг, не мелкое улучшение UI), я обязан:

1. Добавить запись в начало массива `WHATS_NEW` в `src/lib/whatsNew.ts` (date, title, description на русском, кратко).
2. Обновить константу `WHATS_NEW_VERSION` на текущую дату (YYYY-MM-DD), чтобы пользователи увидели бейдж «Новое».
3. Если массив стал длиннее ~12 записей — удалить самые старые (показываем только последние 5, храним ~10).
4. Добавить соответствующий пункт в массив `features` в `src/pages/Guide.tsx` с подходящей иконкой из lucide-react.
5. Добавить новый шаг в массив `demoSteps` в `src/pages/Demo.tsx` (с порядковым номером в title и mock-визуализацией). Иконки импортируются в шапке файла.

**Что считается «новой функцией»:** новая страница, новый раздел UI, новая возможность экспорта, новая интеграция, новый тип ввода данных, новая автоматизация. НЕ функции: исправление багов, изменение стилей, переименование кнопок, оптимизация производительности.

**Why:** Пользователь хочет видеть актуальный список новых возможностей в шапке и в Руководстве без отдельного механизма автогенерации — это памятка для AI, а не код.
